# IzumxAI stage 2 — обучение, память и проверка переноса навыков

Дата: 3 ноября 2026. Приоритет: код и решение задач, компактная работа на ноутбуке.

## Результат и выбранный вариант

Обучен QLoRA-адаптер Qwen3-1.7B и собраны отдельные GGUF Q4_K_M для чекпоинтов
20 и 57. Экспериментальный тег `izumxai:2b-stage2` указывает на чекпоинт 20:
он лучше на локальном русскоязычном наборе. Дополнительная внешняя проверка
показала регрессию относительно обеих базовых моделей по коду. Итог смешанный;
общее превосходство над моделями такого размера не подтверждено.

```powershell
ollama run izumxai:2b-stage2 --think=false
```

Теги для сравнения:

* `izumxai:2b-stage2` и `izumxai:2b-stage2-step20` — ранний кандидат.
* `izumxai:2b-stage2-step57` — последний шаг, лучший по validation loss.
* `izumxai:2b` — предыдущая версия, отдельная базовая линия.
* `qwen3-local:1.7b` — исходная Qwen3-1.7B, экспортированная тем же конвертером
  и квантованная в Q4_K_M.

Выбранный GGUF: `models/izumxai-2b-stage2-step20/gguf/izumxai-2b-Q4_K_M.gguf`.
Размер: **1 107 408 832 байта**, приблизительно **1,03 GiB**.

эталонных решения из банка кода после запуска проверок. После удаления
повторяющихся условий осталось 338 уникальных примеров: 304 train и 34 val.
Сохраняется первый проверенный ответ на повторяющееся условие.

## Измерение памяти

Физическое устройство: RTX 4050 Laptop GPU с 6141 MiB, Windows WDDM.
Лимит аллокатора PyTorch — 3,25 GiB; полное потребление дополнительно
измерялось `nvidia-smi` примерно раз в секунду.

* Пик выделенной памяти PyTorch за успешный обучающий запуск: **2,419 GiB**.
* Общий пик GPU-памяти, включая фоновые программы: **4250 MiB**, или **4,15 GiB**.
  Он возник при загрузке/подготовке; исходное фоновое потребление — 942 MiB.
* В основной части обучения общий расход составлял примерно 3,1–3,3 GiB.
* Общий измеренный пик генерации на внешней выборке: **2462 MiB**, или **2,40 GiB**,
  при `num_ctx=2048`, `num_predict=512`, отключённом thinking.

В проверенном режиме инференс имеет запас относительно 4 GiB. Полный обучающий
запуск на физической карте с 4 GiB не проверен; суммарный пик этой машины
превышал этот объём. Интервал выборки раз в секунду может пропустить более
короткие пики.

Первые два запуска с тем же лимитом аллокатора завершились OOM. Их журналы
сохранены. Успешный путь включает две оптимизации:

1. Проекция на словарь выполняется только для позиций, предсказывающих
   размеченные токены ответа. Внимание к промпту сохраняется. Лосс и все
   градиенты сопоставлены с обычным полным расчётом, в том числе с LoRA.
2. После подготовки k-bit замороженные embedding/output-матрицы возвращаются
   из FP32 в исходный BF16; нормализации остаются FP32. Для связанной матрицы
   словаря это экономит примерно 0,58 GiB. После validation освобождается
   неиспользуемый CUDA-кэш перед следующей фазой обучения.

## Проверки качества

Одинаковые условия: Q4_K_M, общий raw-промпт через один локальный шаблон Qwen3,
`enable_thinking=False`, temperature=0, seed=20261103, контекст 2048, максимум
512 новых токенов. Условия и эталонные тесты не отправлялись на дообучение.
Код оценивается по функциональным тестам, без полного контроля ограничений
на реализацию и асимптотику. Генерация была примерно 129–131 токен/с;
это скорость декодирования Ollama без времени загрузки и выполнения тестов.

### Локальный набор: 24 задачи

| Модель | Код | Математика | Логика | Всего |
|---|---:|---:|---:|---:|
| Qwen3-1.7B Q4_K_M | 8/12 | 5/6 | 5/6 | 18/24 |

Набор зафиксирован до первого сравнения моделей. После проверки шага 57
он использовался повторно для выбора раннего чекпоинта, поэтому это локальный
набор разработки, а не независимая финальная оценка выбранного шага.
Проверка точных нормализованных условий не нашла пересечений с записанными
обучающими данными; это не аудит содержимого исходного предобучения Qwen.

### Дополнительная проверка: 12 задач HumanEval

После выбора шага 20 зафиксирована случайная выборка
`random.Random(20261103).sample(items, 12)` из 164 задач
[HumanEval](https://github.com/openai/human-eval). Использованы исходные
`check(candidate)` и проверенные canonical solutions. Instruction-промпт
адаптирован для возврата полной функции. После получения результатов
чекпоинт не менялся и дальнейшее обучение не проводилось.

| Модель | Пройдено функциональных проверок |
|---|---:|
| Qwen3-1.7B Q4_K_M | **9/12** |
| Прежняя IzumxAI | 8/12 |
| Новый адаптер, шаг 20 | 7/12 |

Метрика относится к этой малой детерминированной выборке и адаптированному
instruction-режиму. Она не является полным опубликованным HumanEval pass@1.
Датасет, seed, SHA-256 и список ID сохранены в `data/eval/`; рядом находится
MIT-лицензия исходного набора.

## Артефакты и воспроизведение

* `runs/stage2-20261103/manifest.json` — данные, настройки и хеши исходников.
* `runs/stage2-20261103/results_summary.json` — объединённые ответы, оценки и память.
* `runs/stage2-20261103/train-v3.log` — успешное обучение.
* `runs/izumxai-2b-stage2-4gb-v3/` — адаптеры, история validation и метаданные.
* `data/eval/stage2_holdout.jsonl` — локальные 24 задачи.
* `data/eval/humaneval_stage2_12.jsonl` — внешняя выборка с оригинальными тестами.

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -m izumxai.eval.holdout `
    --models izumxai:2b-stage2,izumxai:2b,qwen3-local:1.7b `
    --exclude-data runs/stage2-20261103/curriculum.jsonl `
    --out runs/stage2-20261103/recheck-local.json
.\.venv\Scripts\python.exe -m izumxai.eval.holdout `
    --tasks data/eval/humaneval_stage2_12.jsonl `
    --models izumxai:2b-stage2,izumxai:2b,qwen3-local:1.7b `
    --exclude-data runs/stage2-20261103/curriculum.jsonl `
    --out runs/stage2-20261103/recheck-external.json
```

Прошли 14 автоматических тестов. Проверены обычный Ollama chat и второй ход
с сохранением контекста: функция `safe_divide` проходит граничные случаи.
При запросе аннотаций модель указала `float`, хотя возвращает также `None`;
эта ошибка типов записана в `native_smoke.json`.

Генератор данных остаётся остановленным на 418 примерах. Возобновление:

```powershell
.\.venv\Scripts\python.exe -m izumxai.distill.gen_data `
    --n 1100 --level hard --seed 7 --out data/distill/train.jsonl
```

Следующее изменение данных должно расширять разнообразие кода и проверять
рассуждения, а не только финальное число ответа. Приёмка следующего кандидата
должна включать отдельную проверку кода и свежую внешнюю оценку; одного
минимума validation loss недостаточно.
