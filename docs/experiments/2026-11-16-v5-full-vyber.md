# Stage 7 — IzumxAI-9B v5: обучение на полном Vyber07/cyber-security

Дата: 16 ноября 2026. Оборудование: RTX 4080 SUPER 16 ГБ, 64 ГБ RAM, диск D:.

Цель: тот же 9B-ученик, но обученный не на 2.1 тыс. примеров из датасета, а
на полном объёме его текстовых источников (~3.2 ГБ), без потери
кода/математики/логики и с сохранённой abliteration.

## Подготовка данных

`izumxai/distill/download_vyber_v5.py` — качает 6 файлов (3.2 ГБ).

`izumxai/distill/prepare_vyber_v5.py` — стриминговый отбор:

- фильтры как в v4 (без `<think>`, без отказов, без битых код-блоков,
  лимит 6500 символов, минимум 200 символов ответа);
- новые проверки: «ответ — только ссылки», низкая энтропия ответа;
- **выборка по хешу**: на домен берётся не первые N записей, а N с
  наименьшим хешем — иначе из 2.5-ГБ файла учили бы только начало;
- дедуп по user/паре **против данных v4** (3 288 пар), чтобы не повторять
  уже выученное.

Прогон: 1 980 415 записей прочитано, 1 910 003 нормализовано,
119 065 отброшено фильтрами (117 788 — слишком короткий ответ),

## Обучение

QLoRA `Qwen/Qwen3.5-9B`, r=32/alpha=64, 2048 контекст, **1 эпоха**
(данных в 2.8 раза больше, чем в v4), grad-accum 8, lr 2e-4, vram-budget 15 ГБ.
Далее merge → abliteration 1.4 → GGUF Q4_K_M/Q5_K_M → `izumxai:9b-v5`,
`izumxai:9b-v5-q5`.

Скрипт: `scripts/16_v5.ps1`.

Прогон: 1 107 шагов, 626 tok/s, ~1.6 ч на обучение. Обучаемых параметров
86.6 млн (0.91% от 9.50 млрд), LoRA на 12 модулях (attention + MLP + SSM-ветка
`in_proj_*`/`out_proj`).

| | v4 | v5 |
|---|---|---|
| train / val | 3 161 / 71 | 8 917 / 187 |
| токенов train | 1.16M | 3.64M |
| шагов | 786 | 1 107 |
| val loss до / после | 0.8662 → 0.3198 | 1.2262 → **0.7003** |

Val loss у v5 выше не потому, что модель хуже: валидация состоит из тех же
трудных внешних диалогов (сценарные cyber-ответы, CVE-триаж), а не из лёгких
проверенных пар, как в v4. Сравнивать между версиями эти числа нельзя.

### Правка сборки датасета

Первый запуск упал на `ValueError: prompt is not a prefix of the completed
conversation`: ~74 внешних примера содержат CoT-текст **без** `<think>`-тегов,
и шаблон Qwen рендерил промпт с пустым think-блоком, а полную
последовательность — с рассуждением. В `izumxai/distill/common.py`
`build_labeled_example` теперь пробует оба варианта шаблона
(`enable_thinking=True/False`) и при отсутствии префикса отбрасывает пример
вместо падения. После правки: 8 850/8 917 train и 185/187 val (0.8% и 1.1%
отброшено), регрессия на v4-данных — 3 141/3 161.

## Результаты

### Свой бенч (88 задач, `--n-cyber 24 --num-predict 1100 --level mix --seed 42`)

| тип | v3-14 | v4 | **v5** |
|---|---|---|---|
| math | 24/24 | 24/24 | **24/24** |
| logic | 11/12 | 11/12 | **10/12** |
| code | 15/16 | 15/16 | **16/16** |
| instruction | 10/12 | 10/12 | **7/12** |
| cyber | 21/24 | 20/24 | **19/24** |
| **итого** | 82/88 (93%) | 80/88 (91%) | **78/88 (86%)** |

Отказы: **0 из 41** (как и у v4).

Что видно:

- **Код и математика не пострадали** — 16/16 и 24/24, это лучший результат
  по коду среди всех версий.
- **Cyber 19/24** — на две задачи ниже v3: полный датасет добавил
  «рассуждательности», но не фактической точности на CVE/лог-вопросах.
  Промохи — там, где нужен ровно один токен (`SHA-1`, `MD5`, `firewall37`).
- **Instruction 7/12 (58%)** — главная регрессия. Причина видна на
  sanity-прогоне: модель теперь начинает ответ с мета-нарратива
  («Here's a thinking process that leads to…») и болтает, вместо того чтобы
  выдать ровно запрошенный формат. Это прямой артефакт обучения на «сыром»
  CoT из внешнего датасета (рассуждения без `<think>`-тегов).
- Скорость упала до 33 tok/s — модель генерирует длинные рассуждения
  практически на любой промпт.

Вывод: полный датасет дал более глубокую кибер-эрудицию и идеальный код, но
ценой дисциплины формата.

### Разбор провалов instruction

Проверил `runs/bench.json` глазами — это не сломанный формат, а два конкретных
механизма:

- «Сократи до одного предложения»: ответы по смыслу верные, но 27–30 слов при
  лимите проверки 25 (`_instr_short`). То есть модель не уложилась в длину.
- «Сколько слов в тексте?»: ответы `5` и `4` вместо фактического числа — модель
  считает по «ощущению», а не по тексту. У v4 эти же задачи проходили.

Мета-нарратив («Here's a thinking process…»), замеченный на sanity-прогоне,
в данных почти отсутствует: регулярка по 8 917 строкам нашла **1** такой
пример. Значит это не заученная фраза, а общая «болтливость» после обучения на
длинных рассуждениях.

### Правка провайдера бенчмарков

`ollama.py::_strip_reasoning` вырезал только парные `<think>…</think>`. У v5
часть рассуждений идёт без открывающего тега, поэтому в ответ попадал весь
монолог. Добавлено удаление «осиротевшего» `</think>` (всё до него
отбрасывается). Оба прогона v3/v5 запущены на одном и том же коде.

### План v5.1 (не запускался)

В `mix_v5.py` добавлен `--stage5-repeat N` — повтор проверенной части
(stage5) относительно внешних данных. Гипотеза: 2× повтор вернёт дисциплину
формата (instruction 7/12 → 10–11/12), не теряя кибер-эрудицию. Запускать
имеет смысл только после того, как станут известны метрики CyberSecEval v5:
если v5 там заметно лучше v4, есть что сохранять.
