# v6: execution-verified agentic SFT

Дата: 2026-11-19.

## Задача

Харнесс (см. `2026-11-18-v4-agentic-harness.md`) показал три пробела у модели
без эскалации (`--escalate-after 0`):

| пробел | замер |
| --- | --- |
| `eval()` → RCE | 0/8: модель пробует `1+2` или `printenv IZUMX_TOKEN`, но не выражение, исполняющее код |
| после `NOT SOLVED` | повторяет свой же payload вместо смены конструкции |
| поисковые инструменты | не вызывает `try_variants` / `surviving_separators`, даже когда промпт это разрешает |

Цель v6: закрыть их, не потеряв остальное. Условие приёмки прежнее: новая
версия displaces v4 только если лучше по всем осям (88-задачный текстовый бенч
и 0 отказов) плюс рост «чистой» агентной метрики.

## Почему данные проверяются исполнением

Обычная имитация здесь опасна: если «золотое» действие не работает, модель
учится уверенно врать (ровно это и наблюдалось в одношаговом POC — два ложных
«готово»). Поэтому `izumxai/agentic/synth.py`:

1. поднимает настоящий сервис в WSL на свободном порту;
2. выполняет действие через тот же `Tools`, что и харнесс;
3. оставляет пример только если оракул увидел токен в stdout сервиса;
4. для каждого «провального» пункта в контексте (`уже пробовал`) отдельно
   проверяет, что он действительно не решает задачу.

Токен в env сервиса, PoC его не видит, поэтому подделать метку нельзя.

## Что сгенерировано

13 вариантов стендов (не 4 исходных, чтобы модель не выучила дословный текст):

- command injection без фильтра — 3 (разные эндпоинты/параметры);
- command injection с блэклистом — 2 рабочих фильтра
  (`[;&|`$()]`, `[;&|]`) + 1 негативный контроль
  (`[;&|`$()\n\r]` — не решается ничем, примеры не эмитятся);
- path traversal — 3;
- `eval()` — 3.

На каждый вариант:

- прямые примеры: пустая история → рабочий payload;
- recovery: 2–4 реально провальных payload в «уже пробовал» → другая
  конструкция, которая решает;
- поиск: 2–4 провала → `try_variants` (проверен на свежем стенде: решает) или
  `surviving_separators` (отчёт содержит разделитель, входящий в уже
  подтверждённый payload).

Итог: **158 примеров**, 1.1 МБ, все `verified: true`.

| класс | примеров |
| --- | --- |
| `agentic:cmd` | 62 |
| `agentic:eval` | 40 |
| `agentic:cmd_filter` | 30 |
| `agentic:path` | 26 |

Инструменты в ответах: `try_payload` 134, `try_variants` 14,
`surviving_separators` 10.

Длина после chat-шаблона Qwen3.5: min 1428, p50 1513, p90 1563, max 1590
токенов — все примеры проходят `--max-len 2048` и не режутся.

## Смесь v6

`mix_v4` расширен флагами `--agentic` и `--agentic-repeat`, поведение по
умолчанию не изменилось.

```
stage5 train 1038 + vyber 2183 + agentic 158x3 = 3611
val 135 (8 agentic)
состав: vyber 2123, cyber 651, agentic 450, math 223, logic 76,
        instruction 56, code 32
```

Agentic — 12.5% смеси. Повтор x3 нужен потому, что 158 строк иначе теряются в
3 тысячах, а поведение (выбор инструмента) формируется частотой.

Обучение: QLoRA, `r=32`, `alpha=64`, 2 эпохи, `lr=2e-4`, `max-len 2048`,
`vram-budget-gb 15`, абliteration scale 1.4 — тот же рецепт, что v4.

```
powershell -ExecutionPolicy Bypass -File scripts\19_v6.ps1
```

## Воспроизведение данных

```powershell
cd D:\IzumxAI\repo
$env:PYTHONUTF8="1"
.venv\Scripts\python.exe -u -m izumxai.agentic.synth `
    --out data\distill\agentic_sft.jsonl
```

Генератор печатает по каждому варианту число подтверждённых и провальных
payload. Если у варианта нет ни одного подтверждённого действия, он падает с
ошибкой — молча выдать непроверенные примеры нельзя. Единственное исключение —
негативный контроль, у которого positives пуст по замыслу.
