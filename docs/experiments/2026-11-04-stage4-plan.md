# Stage 4: датасет с проверкой крайних случаев — состояние работ

Дата: 4 ноября 2026. Точка остановки для продолжения работы.

## Цель

Довести компактную модель IzumxAI (1.7B, Q4_K_M, тег `izumxai:2b-v4`) выше
текущего результата на HumanEval и проверить её честным замером против
`qwen3:8b` и предыдущих версий.

## Что сделано в этой итерации

Новые файлы:

- `izumxai/distill/gen_plan.py` — генератор данных. Два шага на пример:
  1) учитель qwen3:8b пишет только код (temperature 0.2, cap 900);
  2) отдельным запросом проверяет решение на крайних случаях (temperature 0.3,
     cap 420). Текст проверки кладётся в `<think>`, финальный код — после него.
  В датасет попадает только код, прошедший официальные тесты MBPP или
  проверку банка алгоритмических задач.
- `izumxai/distill/assemble_stage4.py` — смешивает примеры с проверкой
  (повтор ×2) с проверенными данными stage3, откладывает часть примеров
  в валидацию, следит, чтобы промпты не пересекались между train и val.
- `izumxai/distill/data_stats.py` — состав, длины ответов и доля `<think>`.
- `izumxai/eval/compare.py` — что исправлено и что сломано между двумя
  отчётами решателя.
- `scripts/12_stage4_plan.ps1` — gen → assemble → train → merge/GGUF → ollama.
- `scripts/13_eval_stage4.ps1` — единый бенч, быстрый прогон на 12 задачах,
  полный HumanEval.
- Тесты: `tests/test_distill.py::Stage4Assembly`,
  `tests/test_distill.py::TrainingExamples::test_reasoning_answer_keeps_its_thinking_trace`,
  `tests/test_code_tasks.py::ThinkDataChecks` — проходят.
- `izumxai/distill/common.py` — `build_labeled_example` включает
  `enable_thinking=True`, если ответ ассистента начинается с `<think>`,
  иначе шаблон вставлял пустой `<think></think>` и учил «думать ни о чём».

## Почему не сырые рассуждения учителя

Замерено на этой машине (RTX 4050 Laptop, 6 ГБ, qwen3:8b Q4_K_M):

- родной режим `think=True`: 15–17 ток/с, но 1500–2500 токенов на простую
  задачу MBPP; при cap 1536 ответ обрывается до кода. Это 2–4 минуты на пример,
  то есть 10+ часов на 260 примеров;
- просьбы «думай кратко» и формат `<think>` в обычном режиме модель игнорирует;
- двухшаговая схема (решение + отдельная проверка) даёт ~2 примера/мин
  и осмысленный текст проверки.

Поэтому дистиллируется не многословный CoT, а привычка проверять крайние
случаи перед финальным кодом.

## Текущее состояние (на момент остановки)

В фоне запущена генерация:

```
python -u -m izumxai.distill.gen_plan --n 260 --mix mbpp:80,alg:20 \
    --out data/distill/stage4-plan/train.jsonl
```

- лог: `runs/gen_plan.log`
- данные: `data/distill/stage4-plan/train.jsonl` (дописывается, можно прерывать)
- скорость ~2,1 примера/мин, на момент записи 7 из 260 → осталось ~2 часа
- брак: единичные неверные решения учителя, они отбрасываются проверкой

Фоновый процесс живёт только в текущей сессии. Если он остановился — команду
можно запустить заново: уже готовые примеры распознаются по промпту и не
дублируются.

## Как продолжить

1. Проверить прогресс:

```powershell
Get-Content runs\gen_plan.log -Tail 2
(Get-Content data\distill\stage4-plan\train.jsonl | Measure-Object -Line).Lines
```

2. Если генерация не идёт — перезапустить из `E:\IzumxAI` (PowerShell, cp1251-консоль):

```powershell
$env:PYTHONIOENCODING="utf-8"
.\.venv\Scripts\python.exe -u -m izumxai.distill.gen_plan --n 260 --mix mbpp:80,alg:20 --out data\distill\stage4-plan\train.jsonl
```

3. Собрать датасет и посмотреть статистику:

```powershell
.\.venv\Scripts\python.exe -m izumxai.distill.assemble_stage4 --think data/distill/stage4-plan/train.jsonl --plain data/distill/stage3-smel/train.jsonl --plain-val data/distill/stage3-smel/val.jsonl --out data/distill/stage4
.\.venv\Scripts\python.exe -m izumxai.distill.data_stats data/distill/stage4/train.jsonl data/distill/stage4/val.jsonl
```

4. Обучить (или целиком `scripts\12_stage4_plan.ps1`):

```powershell
$env:HF_HOME="E:\IzumxAI\.cache\hf"
.\.venv\Scripts\python.exe -u -m izumxai.distill.train_lora --data data/distill/stage4/train.jsonl --val data/distill/stage4/val.jsonl --out runs/izumxai-2b-plan-lora --epochs 2 --batch-size 1 --grad-accum 8 --max-len 1024 --lr 2e-4 --lora-r 32 --lora-alpha 64 --vram-budget-gb 4.5 --eval-every 40
```

5. Merge → GGUF → Ollama:

```powershell
.\.venv\Scripts\python.exe -m izumxai.distill.merge_export --adapter "runs/izumxai-2b-plan-lora/final" --base Qwen/Qwen3-1.7B --out "models/izumxai-2b-v4" --gguf --quant Q4_K_M
ollama create izumxai:2b-v4 -f "models/izumxai-2b-v4/Modelfile"
```

6. Замерить:

```powershell
.\scripts\13_eval_stage4.ps1 -Model izumxai:2b-v4 -Rounds 3
.\.venv\Scripts\python.exe -m izumxai.eval.compare runs\solver\humaneval-think-r3.json runs\solver\humaneval-stage4-r3.json
```

7. Записать результат в этот файл (или новый отчёт в `docs/experiments/`)
и обновить `README.md` реальными числами. README сейчас в cp866 —
перезаписать в UTF-8.

## На что смотреть при замере

- Если `izumxai:2b-v4` ниже 111 — значит, короткий план не даёт того,
  что даёт промпт-уровневое «думай и проверяй»; тогда следующий шаг —
  native-think дистилляция на 40–60 задачах (дорого по времени) или ORPO
  на парах, добытых решателем.
- Если выше 116 — сравнить с `qwen3:8b` на едином бенче
  (`izumxai.eval.bench`), только после этого говорить о превосходстве.
- 12-задачный быстрый прогон — только сигнал, не результат.
