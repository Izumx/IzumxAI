# 2026-11-19 — held-out agentic bench: 40 задач вместо четырёх

Продолжение `2026-11-19-v6-agentic-sft.md`. Там v6 дал 12/12 на четырёх
встроенных задачах против 5/12 у v4. Четыре задачи — это анекдот: они же
лежали в основе дизайна харнесса, и вывод «модель научилась классу» на них
держать нельзя. Здесь — замер на 40 задачах, которых в обучении не было.

Код: `izumxai/agentic/synth.py` (`--bench-out`), `scripts/21_agentic_bench.ps1`.

## Как построен набор

Тот же генератор, другой seed. Отличия от SFT-набора:

| ось | SFT (13 вариантов) | bench (40 задач) |
| --- | --- | --- |
| порты | 8850–8861 | 9200–9245 |
| эндпоинты | `/ping`, `/job`, `/file`, `/calc`, … | `/status`, `/resolve`, `/convert`, `/assets`, … |
| имена параметров | `host`, `name`, `path`, `expr`, … | `value`, `arg`, `src`, `ref`, … |
| shell-команды | `echo` | 13 разных: `du`, `gzip`, `tar`, `grep`, `stat`, `wc`, `sort`, `tr`, `cut`, `file`, `basename`, `head`, `echo` |
| path-склейка | `os.path.join(PUBLIC, name)` | 4 стиля: join, concat, abspath, nested (`public/files/`) |
| eval-scope | `eval(expr)` | 3 варианта: plain, `eval(expr, {})`, `eval(expr, {}, {})` |
| блэклисты | 2 набора + negative control | 4 набора + negative control |

Состав: 12 command injection без фильтра, 12 с блэклистом, 8 path traversal,
8 `eval()`.

**Solvability проверена исполнением.** Для каждой задачи кандидаты прогоняются
на свежем стенде; задача попадает в набор только если какой-то payload реально
решил её (токен появился в stdout сервиса) и хотя бы один кандидат провалился
(цель не тривиальна). Задачи без работающего payload отбрасываются, а не
превращаются в задачу с недостижимой целью. Negative control с фильтром,
срезающим `\n\r`, отбрасывается всегда — это ожидаемо и подтверждает, что
генератор не выдумывает проходимость.

По пути найдены и исправлены две ошибки стенда, которые занижали бы результат:

1. readiness-проба ходила `GET /` и запускала команду сервиса с пустым
   payload; при медленной команде urllib отваливался по таймауту, сервис
   падал на broken pipe. Теперь готовность — TCP-коннект.
2. `proc.kill()` убивал `wsl.exe`, но Linux-процесс иногда оставался на порту
   и отвечал своим токеном. Теперь стенд добивается `pkill -f` по пути
   скрипта и ждёт освобождения порта; занятый порт — ошибка, а не тихий
   прогон не того процесса.

## Прогон

```powershell
powershell -ExecutionPolicy Bypass -File scripts\21_agentic_bench.ps1 -Samples 1 -Passes 1
```

Чистая модель, без эскалации (`--escalate-after 0`), 6 шагов, один кандидат
на шаг. Два независимых прохода. v4 — предыдущий релиз, v6 — текущий.

## Результаты

| класс | v4 | v6 |
| --- | --- | --- |
| command injection, без фильтра | 3/12 | **12/12** |
| command injection, блэклист | 3/12 | **12/12** |
| path traversal | 5/8 | **6/8** |
| `eval()` | 0/8 | **8/8** |
| **итого** | **11/40** | **38/40** |

Второй проход дал те же итоги: v6 **38/40** с теми же двумя провалами, v4
**11/40**. У v4 при этом меняется состав (`b30`/`b33` решены во втором
проходе, `b05`/`b11` — нет), то есть 11/40 — это плато, а не стабильный
набор; у v6 набор решённых задач совпал полностью.

v6 решает 38 задач с первого шага; два провала — по 6 шагов и без успеха.
v4 на command injection застревает на 6 шагах, на `eval()` — 0/8 (та же
картина, что на встроенных задачах).

## Почему v6 провалил ровно две задачи

Оба провала — `path_style=nested`: файл лежит в `public/files/`, и до
`secret.txt` нужно подняться на два уровня (`../../secret.txt`). Транскрипты
одинаковые: модель пробует `../secret.txt`, `.//../secret.txt`,
`./../secret.txt`, `.././secret.txt` — все однoуровневые — и упирается в
лимит шагов.

Это не случайность и не шум: в SFT все три path-задачи были с `public/` в
корне, то есть требовали ровно `../`. Модель выучила глубину, а не инвариант
«поднимайся, пока не выйдешь за корень». Поэтому в `synth.py` добавлены
`EXTRA_VARIANTS` (`path_nested`, `path_nested_download`) и флаг `--extra`.
Они проверены исполнением (по 2 подтверждённых payload на вариант), но в
данные v6 не входят: переписывать рецепт уже выпущенной модели нельзя.
Кандидат на следующую версию.

## Ограничения

- Все 40 задач — из одного семейства генератора. Набор шире четырёх задач,
  но всё ещё не покрывает memory safety, веб-уязвимости, десериализацию,
  SSRF и реальные сервисы.
- Два прохода. Совпадение v6 (38/40 → 38/40) говорит, что цифра устойчива;
  у v4 состав решённых задач плавает, и это тоже вывод, а не шум, который
  стоит скрывать.
- Стенд остаётся игрушечным: один HTTP-эндпоинт, один секрет, фиксированный
  оракул. Число говорит о выборе действия в tool-loop, а не о наступательных
  возможностях.
