# SMEL FT assessment for dense Qwen3-1.7B

Research date: 2026-11-03. Upstream checkout: `tools/smel-ft`, commit **`74a4635d5f7733baae9915d291573fae94a0499b`**, version 0.3.0. This assessment reads the pinned README and source; no dependencies were installed and no GPU jobs were run for the research.

Evidence labels used below: **upstream claim** means an author-reported experiment; **source verified** means directly established by reading the pinned source or existing local artifacts; **inference/recommendation** means a proposed adaptation requiring its own tests.

## Recommendation

**Adapt the useful parts, with a separate dense Qwen3 path. Do not run the upstream MoE pipeline against our checkpoint.** Start with the actual upstream `smel.loss.LMHead` and `chunked_ce`, a deterministic frozen-prefix cache, and LoRA restricted to a small upper block of native Transformers Qwen3 layers. Keep the existing full QLoRA trainer and current adapters available for comparison. This is an experiment in training memory and task preservation; source reading does not establish a quality improvement or a physical 4 GiB training fit.

The primary blockers are architectural, not the installed Torch version. Upstream lists only `qwen3_5_moe` and MoE `gemma4`; `Dims.from_config()` falls through to required linear-attention/MoE keys for ordinary `qwen3`, so our config would fail rather than discover a dense implementation. Its default Qwen norm convention is also different. [Pinned model dimensions and dispatch](https://github.com/artikulus1301/smel-ft/blob/74a4635d5f7733baae9915d291573fae94a0499b/smel/model_io.py#L19-L116).

## Reusable components

1. **Cached frozen prefix. Source verified:** `run_bottom()` streams layers `[0,L)` once with no gradients, then stores BF16 inputs of layer `L`. `HiddenStore` uses a NumPy uint16 representation preserving BF16 bits. **Inference:** this principle transfers to dense Qwen3 when embeddings and prefix stay fixed and inference semantics match. A 2048-wide BF16 boundary costs 4096 bytes/token, about 391 MiB per 100000 tokens per cache copy, before metadata and temporary buffers. [Bottom pass](https://github.com/artikulus1301/smel-ft/blob/74a4635d5f7733baae9915d291573fae94a0499b/smel/bottom.py), [hidden store](https://github.com/artikulus1301/smel-ft/blob/74a4635d5f7733baae9915d291573fae94a0499b/smel/pipeline.py#L178).
2. **Upper-block training. Source verified:** upstream chooses a cut from domain/general router divergence and expert sets by gate mass, then optionally streams an upper block layer by layer with explicit recompute/backward. **Inference:** router statistics have no analogue in this dense model. Choose a few candidate cuts by a predeclared memory/quality comparison; do not call an arbitrary top-eight-layer cut router-selected SMEL. Native Transformers layers plus upper-layer PEFT LoRA are a smaller adaptation than porting the custom MoE runner. [Selection](https://github.com/artikulus1301/smel-ft/blob/74a4635d5f7733baae9915d291573fae94a0499b/scripts/select_experts.py), [runner](https://github.com/artikulus1301/smel-ft/blob/74a4635d5f7733baae9915d291573fae94a0499b/smel/layer_runner.py#L295).
3. **Frozen-head chunked CE. Source verified:** `chunked_ce(h, head, tgt, denom, token_chunk)` consumes final-normalized supervised hidden rows and target IDs. The online log-sum-exp implementation accumulates the hidden gradient while iterating vocabulary tiles. This avoids full supervised-token-by-vocabulary logits; it does retain hidden gradients and intermediate tiles. Defaults are token chunk 1024 and vocabulary chunk 32768, so smaller chunks are appropriate under our memory budget. BF16 or per-row int8 heads are available. [Loss implementation](https://github.com/artikulus1301/smel-ft/blob/74a4635d5f7733baae9915d291573fae94a0499b/smel/loss.py).

An unquantized tied matrix is 151936 × 2048 × 2 bytes, about 593.5 MiB; int8 data is about 296.8 MiB plus row scales. An int8 training head changes the objective slightly, so compare against its dequantized weight first and separately measure end-to-end behavior after export. The upstream int8 test compares to the dequantized head, not the original BF16 head. [Loss tests](https://github.com/artikulus1301/smel-ft/blob/74a4635d5f7733baae9915d291573fae94a0499b/tests/test_loss_single_pass.py).

## Correctness requirements for the dense adaptation

**Source verified locally:** installed `transformers/models/qwen3/modeling_qwen3.py` returns a hidden tensor from each decoder layer, creates rotary positions and masks in `Qwen3Model.forward`, iterates original layer indices, and applies the final norm once after the loop. It supports `inputs_embeds`. Consequently, identity replacements for prefix layers must accept the extra keyword arguments and return the tensor, not an older Transformers tuple. Preserve the original numbering, layer types, and self-attention layer indices. Pass `use_cache=False`; the training feature cache is distinct from autoregressive KV caching.

**Recommendations:**

- Capture the state immediately before layer `L`, including both prompt and answer token positions. Do not capture a final-normalized state or apply the final norm twice.
- Freeze embeddings and all prefix layers before generating caches. Disable prefix dropout and any training-time stochastic behavior. Attach no adapter below `L`.
- Build a cache identity from base weights/revision, tokenizer files and template, full token IDs, sequence offsets, exact padding/masks/position scheme, cut `L`, dtype, and relevant backend/version. Write atomically. Token concatenations alone cannot identify causal sequence boundaries.
- Keep samples unpadded during cache creation or reproduce their masks/positions exactly. If packing, use block-diagonal causal masks and reset positions; plain concatenation allows information to flow across independent examples.
- Run a tiny deterministic full-forward versus cached-suffix hidden/logit parity test and an upper-LoRA gradient parity test before the real model. Check layer `L=0`, a middle cut, and a near-final cut. Test padded batches, sequence boundaries, final norm placement and token shift.
- Convert our labels to valid next-token rows exactly once: local labels are aligned to token positions, whereas upstream `tgt[t]` already means the target at `t+1`. Use `hidden[:, :-1][labels[:, 1:] != -100]` with matching `labels[:, 1:]`, then divide summed CE by the supervised token count. Accumulated batches should share a token-count denominator rather than equally weighting examples with different answer lengths. [Upstream target encoding](https://github.com/artikulus1301/smel-ft/blob/74a4635d5f7733baae9915d291573fae94a0499b/smel/data.py#L78-L97).

## Concrete upstream issues and bounded improvements

**Source verified:** the loss API deliberately expects prefiltered targets; it has no `ignore_index` behavior. Passing `-100`, negative IDs, or IDs >= vocabulary silently leaves the target contribution unset in `_ce_chunk`. The resulting value/gradient is not CE for that row. It also accepts zero/nonfinite denominators without validation. A reusable wrapper should reject malformed shapes, non-long or out-of-range targets, zero/nonfinite denominators, and nonpositive chunk sizes; filter ignored rows before calling upstream. This is an API hardening need, not evidence that upstream's own caller is wrong: `LayerMajorRunner.head_loss()` correctly filters `-100` first. Test loss and hidden gradients against `torch.nn.functional.cross_entropy` on CPU float32 with uneven chunks and nontrivial gradient scaling. [Loss and caller](https://github.com/artikulus1301/smel-ft/blob/74a4635d5f7733baae9915d291573fae94a0499b/smel/layer_runner.py#L332-L350).

**Source verified:** the custom backward returns gradients only for hidden states; head weights live inside a Python object. A trainable head receives no gradient through this API. Enforce a frozen head, including a frozen embedding when weights are tied. No evidence was found that the one-pass algorithm itself is incorrect; upstream has full-logit float32 parity and BF16 reference comparisons, although those tests require CUDA. Our reuse merits a CPU parity check. [Loss source](https://github.com/artikulus1301/smel-ft/blob/74a4635d5f7733baae9915d291573fae94a0499b/smel/loss.py#L130-L156).

**Source verified:** `sets_signature()` includes concatenated selected IDs, count of sequences and total token count but not offsets, checkpoint identity or execution details. Different boundaries with the same concatenated IDs can collide semantically; changing weights at the same path can reuse stale caches. Strengthen the identity instead of copying this mechanism unchanged. [Cache signature](https://github.com/artikulus1301/smel-ft/blob/74a4635d5f7733baae9915d291573fae94a0499b/smel/bottom.py#L20-L27).

**Source verified:** `choose_L()` divides by total divergence without an all-zero guard; identical distributions give undefined normalized tails. The memory-selection loop can also exhaust reductions and still emit `stream_disk` even when no estimate fits. Neither component is appropriate as a dense-model fit guarantee. Validate finite positive divergence or use an explicit fallback, and fail closed on an unsatisfied memory budget. [Selection source](https://github.com/artikulus1301/smel-ft/blob/74a4635d5f7733baae9915d291573fae94a0499b/scripts/select_experts.py#L41-L46).

## Quality and evaluation limits

**Upstream claims:** persona/domain perplexity improves in its Qwen experiment without a measured general-text perplexity increase. Its own report discloses private training data, 50 held-out prompts, one domain, a base-model judge, and use of held-out data to select learning rate. It does not establish general code or math improvement for dense Qwen3. [Reference experiment and caveats](https://github.com/artikulus1301/smel-ft/blob/74a4635d5f7733baae9915d291573fae94a0499b/docs/results_qwen.md).

**Existing local evidence:** Stage 2 improves the local set to 21/24 but scores 7/12 on the separate HumanEval slice versus 9/12 for the base. This is a small slice, not published full HumanEval pass@1, but demonstrates that a local win can accompany regression elsewhere. [Existing local assessment](../experiments/2026-11-03-stage2.md).

**Recommendation:** preserve the base GGUF, old adapter and Stage 2 candidate; report all comparisons. Compare a no-training cached-suffix baseline, existing QLoRA, and the dense adaptation on identical prompts, decoding settings and quantization. Choose cuts/checkpoints using validation only; evaluate a disjoint external code set once after selection, plus math/instruction preservation and domain loss. Report task-level outcomes and uncertainties without tuning on the final benchmark. A measured memory reduction and a quality result are separate acceptance conditions.
